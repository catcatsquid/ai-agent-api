# 计算机网络 - 传输层

## TCP三次握手

TCP三次握手是建立TCP连接的过程，确保发送方和接收方都准备好通信。

1. 第一次握手：客户端发送SYN报文（SYN=1, seq=x）给服务器，进入SYN_SENT状态。
2. 第二次握手：服务器收到SYN后，回复SYN+ACK报文（SYN=1, ACK=1, seq=y, ack=x+1），进入SYN_RCVD状态。
3. 第三次握手：客户端收到SYN+ACK后，发送ACK报文（ACK=1, seq=x+1, ack=y+1），双方进入ESTABLISHED状态。

三次握手的原因：防止已失效的连接请求到达服务器后造成资源浪费。两次握手无法确认客户端收到了服务器的SYN+ACK。

## TCP四次挥手

TCP四次挥手是断开TCP连接的过程。

1. 第一次挥手：客户端发送FIN报文，表示没有数据要发送了。
2. 第二次挥手：服务器收到FIN后回复ACK，进入CLOSE_WAIT状态。此时客户端到服务器的方向断开，但服务器还可以继续发送数据。
3. 第三次挥手：服务器发送完剩余数据后，发送FIN报文。
4. 第四次挥手：客户端收到FIN后回复ACK，等待2MSL后关闭连接。

TIME_WAIT状态需要等待2MSL（最大报文段寿命）的原因：确保最后一个ACK能到达服务器；让本次连接产生的报文都从网络中消失。

## TCP与UDP的区别

- TCP是面向连接的，UDP是无连接的。
- TCP提供可靠传输，UDP不保证可靠性。
- TCP有流量控制和拥塞控制，UDP没有。
- TCP首部20字节，UDP首部8字节。
- TCP适合文件传输、网页浏览；UDP适合视频直播、DNS查询、游戏。

## 拥塞控制

TCP拥塞控制包括四个算法：慢开始、拥塞避免、快重传、快恢复。

- 慢开始：连接建立后，拥塞窗口cwnd从1开始，每收到一个确认就翻倍（指数增长）。
- 拥塞避免：当cwnd达到慢开始门限ssthresh时，改为线性增长（每轮加1）。
- 快重传：收到3个重复ACK时立即重传丢失的报文，不等超时。
- 快恢复：快重传后ssthresh减半，cwnd设为ssthresh，进入拥塞避免（不回到慢开始）。
