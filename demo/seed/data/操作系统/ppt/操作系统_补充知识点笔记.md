## 一、系统调用与受限直接执行（第6章）

### 系统调用的执行过程

1. **用户态运行**：用户程序正常执行，权限受限
2. **陷入指令**：用户程序执行特殊指令（如 `ecall`/`syscall`），主动请求操作系统服务
3. **切换到内核态**：硬件检测到陷入指令，将 CPU 从用户模式切换到内核模式
4. **保存上下文**：硬件自动保存当前用户态的寄存器（程序计数器、通用寄存器等）到内核栈
5. **查系统调用表**：操作系统根据系统调用号，在系统调用表中找到对应的内核函数入口
6. **执行内核函数**：在内核态中执行请求的操作（如读写文件、创建进程等）
7. **返回用户态**：操作系统执行 `sret`/`iret` 指令，恢复用户态寄存器，切回用户模式
8. **继续执行**：用户程序从系统调用之后的位置继续运行

### 用户态和内核态的切换机制

- **特权级**：CPU 至少有两个特权级别——用户态（低权限）和内核态（高权限）
- **受限操作**：用户态不能直接访问硬件、不能修改页表、不能执行特权指令
- **系统调用是唯一入口**：用户程序只能通过系统调用进入内核态，不能直接跳转到内核代码
- **协作模式**：操作系统通过时钟中断（timer interrupt）定期夺回控制权，防止用户程序霸占 CPU

### 受限直接执行协议

| 阶段 | 操作系统@启动（内核模式） | 硬件 |
|------|------------------------|------|
| 初始化 | 分配地址空间，加载程序到内存 | — |
| 设置陷阱表 | 初始化陷阱表，设置时钟中断 | 记住陷阱地址 |
| 启动定时器 | 启动间隔定时器 | 定时器到期 → 中断 → 内核态 |
| 撤销CPU | 上下文切换到用户态，跳到程序入口 | 恢复用户寄存器，跳到用户程序 |
| 运行 | — | 程序执行受限操作 |
| 系统调用 | 执行陷阱 → 查表 → 执行内核函数 | 保存寄存器到内核栈，切到内核态 |
| 返回 | 执行 sret/iret | 恢复用户寄存器，切到用户态 |

## 二、虚拟内存（第13、21、22章）

### 什么是虚拟内存

虚拟内存是操作系统提供的一种内存管理技术。操作系统为每个进程提供一个**抽象的地址空间**，让每个进程以为自己拥有连续的、独占的内存空间，而实际上物理内存是被多个进程共享的。

### 地址空间的组成

一个进程的地址空间包含：
- **代码段（Code）**：程序的指令，静态的，放在地址空间顶部
- **堆（Heap）**：动态分配的内存（如 `malloc()`/`new`），向下增长
- **栈（Stack）**：函数调用信息、局部变量、参数传递，向上增长

### 虚拟内存的作用

1. **扩大地址空间**：虚拟内存空间可以远大于实际物理内存，通过将不常用的页交换到硬盘
2. **内存保护**：每个进程有独立的虚拟地址空间，互不干扰
3. **内存共享**：多个进程可以共享同一物理页（如共享库代码）
4. **简化编程**：程序员不需要关心物理内存的实际布局
5. **提高多任务能力**：操作系统可以高效地管理多个进程的内存分配

### 虚拟内存的实现机制

- **页表**：每个进程有一个页表，记录虚拟页到物理页帧的映射
- **TLB（翻译后备缓冲器）**：硬件缓存，加速地址转换
- **存在位（Present Bit）**：页表项中标记该页是否在物理内存中
- **页错误（Page Fault）**：访问不在物理内存中的页时触发，操作系统从硬盘换入

### 交换空间（Swap Space）

- 操作系统在硬盘上划出一块区域作为交换空间
- 不常用的页被换出（swap out）到硬盘，需要时再换入（swap in）
- 交换空间的大小决定了系统最大可用内存页数

### 页面置换策略

- **FIFO**：先进先出，最简单的策略
- **LRU**：最近最少使用，淘汰最久没访问的页（效果好但实现复杂）
- **随机**：随机淘汰一页（简单，避免某些最坏情况）

### 实现基础：局部性原理

- **空间局部性**：程序倾向于访问地址相近的数据（如数组遍历）
- **时间局部性**：程序倾向于重复访问最近访问过的数据（如循环变量）
- 虚拟内存有效的前提是大部分时候只访问少部分页面

## 三、分段与分页（第16、18章）

### 分段（Segmentation）

分段是一种内存管理方法，将进程的地址空间按**逻辑单位**划分为若干段：
- 每个段代表一个逻辑单位：代码段、堆段、栈段
- 每个段的大小**不固定**，由段的实际内容决定
- 段表记录每个段的**基址（base）**和**界限（bounds）**

地址转换过程：
1. 硬件从虚拟地址中提取段号和段内偏移
2. 用段号查段表，得到基址和界限
3. 检查偏移是否越界（offset < bounds）
4. 物理地址 = 基址 + 偏移

### 分页（Paging）

分页将进程的地址空间按**固定大小**划分为页：
- 每页大小固定（通常 4KB）
- 物理内存也分为同样大小的**页帧（Page Frame）**
- **页表**记录虚拟页到物理页帧的映射

地址转换过程：
1. 将虚拟地址分为**虚拟页号（VPN）**和**页内偏移**
2. 用 VPN 查页表，得到**物理页帧号（PFN）**
3. 物理地址 = PFN × 页大小 + 页内偏移

### 分页和分段的核心区别

| 对比项 | 分页 | 分段 |
|--------|------|------|
| 划分单位 | 物理单位，大小固定 | 逻辑单位，大小不固定 |
| 用户可见性 | 对用户透明，硬件自动转换 | 用户可见（代码段、数据段等） |
| 地址空间维度 | 一维（线性地址） | 二维（段号 + 段内偏移） |
| 碎片类型 | **内部碎片**（页未填满产生浪费） | **外部碎片**（段间空闲块太小） |
| 共享与保护 | 不便（页是物理单位，无逻辑含义） | 方便（段是逻辑单位，可按段共享/保护） |
| 空间管理 | 简单（固定大小，空闲列表管理） | 复杂（需处理外部碎片，如紧凑） |

### 内部碎片 vs 外部碎片

- **内部碎片**：分配的固定块内有浪费。分页中，进程最后一页可能只用了部分，剩余部分浪费。这是已经分配但未被使用的空间。
- **外部碎片**：未分配的空间太分散，无法满足请求。分段中，段间产生许多小空闲块，单独看都不够用，但总和够。

## 四、锁与临界区（第28章）

### 什么是临界区

临界区是进程中**访问共享资源（临界资源）的那段代码**。在多线程/多进程环境中，必须保证同一时刻只有一个线程在临界区中执行，否则会产生竞态条件。

### 锁的基本概念

锁是保护临界区的最基本同步原语：
- **lock()**：获取锁，如果锁被占用则等待
- **unlock()**：释放锁，唤醒等待的线程
- **互斥量（mutex）**：POSIX 标准中锁的名称，提供线程间互斥

### 进入临界区要遵循的准则

1. **空闲让进**：如果临界区没有线程在执行，且有线程请求进入，则应允许该线程进入
2. **忙则等待**：如果已有线程在临界区中，其他请求进入的线程必须等待
3. **有限等待**：每个请求进入临界区的线程应在**有限时间内**进入，不能无限等待（避免饥饿）
4. **让权等待**：当线程无法进入临界区时，应**释放 CPU**（不让权等待会浪费 CPU 资源做无用功，即"忙等待"）

### 评价锁的三个标准

1. **互斥性（正确性）**：锁是否能有效阻止多个线程同时进入临界区
2. **公平性**：竞争锁的线程是否有公平的机会获取锁，是否会饥饿
3. **性能**：使用锁带来的时间开销

### 锁的实现方式

1. **控制中断**：在临界区关闭中断（单处理器有效，但不适用于多处理器，且不安全）
2. **测试并设置（Test-And-Set）**：原子指令，实现自旋锁
3. **比较并交换（Compare-And-Swap）**：原子指令，比测试并设置更灵活
4. **自旋锁**：线程在获取锁失败时持续循环等待（忙等待），适合短临界区
5. **休眠锁**：获取锁失败时让出 CPU 进入睡眠，适合长临界区

### 自旋锁的优缺点

- 优点：实现简单，无上下文切换开销，适合临界区很短的情况
- 缺点：忙等待浪费 CPU，在单处理器上可能导致死锁，不公平（可能饥饿）

## 五、条件变量（第30章）

### 什么是条件变量

条件变量是一种同步原语，用于线程间**等待某个条件成立**后再继续执行。常与锁配合使用。

### 基本操作

- **wait(cv, lock)**：释放锁，将线程置为休眠状态，等待被唤醒；被唤醒后重新获取锁
- **signal(cv)**：唤醒一个等待在该条件变量上的线程
- **broadcast(cv)**：唤醒所有等待在该条件变量上的线程

### 使用模式

生产者-消费者问题中：
1. 生产者：获取锁 → 检查缓冲区是否满 → 如果满则 wait → 放入数据 → signal 消费者 → 释放锁
2. 消费者：获取锁 → 检查缓冲区是否空 → 如果空则 wait → 取出数据 → signal 生产者 → 释放锁

## 六、信号量（第31章）

### 什么是信号量

信号量是 Dijkstra 提出的同步原语，是一个整型变量 `sem`，配合两个原子操作：

- **wait(sem)**（又称 P 操作）：`while (sem <= 0) 等待; sem--`
- **post(sem)**（又称 V 操作）：`sem++`

### 二值信号量 vs 计数信号量

- **二值信号量**：初始值为 1，等价于锁，用于互斥
- **计数信号量**：初始值为 N，可用于控制对 N 个资源的访问

### 信号量与锁的区别

| | 锁 | 信号量 |
|---|---|---|
| 概念 | 互斥访问 | 控制资源数量 |
| 值 | 0 或 1 | 任意非负整数 |
| 释放者 | 获取者必须释放 | 任何线程都可以 post |
| 典型用途 | 保护临界区 | 资源计数、同步 |

来源：第31章 信号量
