## 一、目标与两条流水线

**目标**：从往年试卷 PDF（**回忆版**）自动提取题目，生成结构化题库，供刷题与复习使用。

系统里其实有**两条**流水线，职责要分清：

| 流水线 | 入口 | 职责 |
|---|---|---|
| **生成管线** | `course_agent/question_bank.py` | PDF → 题图 + 题目 JSON（本文第一～五节） |
| **消费端** | `course_agent/qbank.py` | 读 JSON → 分组出题 / 按题型批改 / 解析卷名 |

---

## 二、核心设计决策（4 条，都有理由）

1. **题目用截图，不用文本** —— 回忆版试卷有大量表格、代码块、图表，
   纯文本提取会丢排版。截图保留原始视觉效果，100% 可读。
2. **答案用 LLM 生成** —— 提取题目文字 + 必要时 VLM 描述图表，喂给 LLM 生成参考答案。
3. **不标 confidence** —— 回忆版本就不可能和原题一模一样，只要题目逻辑完整、
   知识点考察不超纲即可用。**只标 `needs_review`**（格式异常时）。
4. **答案格式统一** —— 选择题 `answer` 只填单字母（A/B/C/D）；
   综合题 `answer=null`，答案全部放在 `sub_questions` 数组里。

> 决策 3 是**用户反馈驱动的**：最初标了 `confidence`（high/medium/low），
> 用户明确说不需要准确度标注；`difficulty` 同样被要求去掉。

## 三、提取管线三代

### v1：LLM 直接拆题

- PyMuPDF 提取全卷文本 → VLM 整页渲染描述有图表的页面 → 合并后喂给 LLM 一次性拆题

**结果**：15/26 道（选择题只提到 9/20，综合题 6/6）。

**问题**：① 选项重复（`question` 与 `options` 各放一遍）；② 图表看不清（银行家算法表格变乱码）；
③ **太慢**（VLM 整页渲染 5 页，全卷 30 分钟）；④ 文本太长导致 API 500；
⑤ `confidence` 标注无用。

### v2：题目截图 + 答案分离

- 题目按题号 y 坐标 `clip` 截图；答案走「VLM 描述图表 → 纯文字调 LLM」两步法；
- 去掉 `confidence`，题干与选项不重复。

**结果**：21/21 选择题截图成功，18/21 答案生成成功。

**问题**：① 截到下一题（`y_end` 取下一题 `y_start` 没留间距）；
② **Q0 误判**（第 6 页表格里的 `0.0` 被当成题号 0）；
③ Q10 跨页被截断；④ 综合题没提取（只匹配了选择题题号）；
⑤ 难度标注无用；⑥ **VLM 400 错误**（GLM-4V-Flash 不支持图片 + 长文本同时发送）。

### v3：最终方案（定稿）

10 处修复：截图边界留 3px 间距、**跨页拼接**（当前页底部 + 下一页顶部拼成一张图）、
Q0 误判修复（正则排除小数 `(?!\d)`）、综合题按大题标题分段并用 `S1-S6` 编号、
综合题编号与选择题隔离、留白裁剪、答案格式统一、`needs_review` 可疑标注、
去掉 `difficulty`、报告里不显示「跨页」标签。

**结果**：**26/26 全部提取**（选择 20 + 综合 6），26/26 答案生成成功，
选择题全部单字母、综合题全部 `answer=null` + `sub_questions`，0 道需审查，
**耗时约 3 分钟**（纯文字题 2~3 秒/题，VLM 题 8 秒/题）—— 比 v1 快 10 倍。

## 四、方向1：结构清洗（208 条，零丢失）

**对象**：`data/question_bank/`（7 套卷，208 条）
**原则**：`debug/qb_clean/clean_qb.py` **默认 dry-run**，`--apply` 才写回；清洗前先备份。

| 指标 | 清洗前 | 清洗后 |
|---|---|---|
| 总条目数 | 208 | 208（**零丢失**） |
| 重复 qid | 41 个（全库 `Q1` 出现 11 次） | **0** |
| type 分类 | 选择题 170 / 综合题 38 | 选择题 159 / 综合题 38 / 填空 6 / 判断 5 |
| schema | 两套混存（9 字段旧 + 18 字段新） | 统一 18 字段 |
| `image`/`images` | 并存且部分不一致 | 归一一致 |
| 图片引用 | — | 203 个引用全部存在 |

**修的五类问题**：

1. **qid 全局唯一** —— 根因：每卷从 `Q1` 重新编号，合并时没加卷前缀；
   且有 3 套卷把不同题型混编进同一 `Q` 系列。
   修法：`qid = 卷前缀_题型字母序号`（填空 `F`、判断 `P`、选择 `Q`、综合 `S`）
2. **类型分类纠正** —— 2019 模拟卷的填空(6)/判断(5) 被错标成 `选择题`，按 `section` 重新归类
3. **schema 统一** —— 2018 秋卷是最老的 pilot 格式（仅 9 字段），补齐可推断字段
4. **`image`/`images` 归一** —— `path` 统一为 `static/qb_images/` 前缀
5. **文本规范化** —— 清除替换符/空字符/尾部空格

**验证方式**：以 `text` 为键比对备份与清洗后 —— 208 条全部匹配，无缺失、无新增。

## 五、方向2：生成管线重构 + 内容补全（208 → 228）

洗完还剩 4 类**内容缺口**：`needs_review` 错标 17 条、2018 秋只存 3 条、
8 条综合题缺 `sub_questions`、撞号卷图片文件名重复引用（串题）。

### 5.1 生成脚本的 4 处 bug

| # | Bug | 根因 | 修复 |
|---|---|---|---|
| 1 | qid 全局撞号 | `locate_questions` 只按「综合」二字识别题型，填空/判断/选择全归 `Q` 系列 | 新增 `classify_category`：section 关键词优先，无关键词则用**区域文本特征**（分值括号→综合、判断框/陈述句→判断、下划线空→填空、`A.` 选项→选择） |
| 2 | 题型误判 | 同一区的填空/判断被 section 里的「选择」吞并 | **文本特征优先于 section 关键词** |
| 3 | 编号撞号 | 四类题型共用一套编号 | 按题型独立计数，`qid = {类型字母}{序号}` |
| 4 | 答案格式错标 | `_check_answer_quality` 对非选择题也一律要求 A-D | 按题型校验：选择→A-D、判断→对/错/√/×/T/F、填空→非空、综合→`null` + 有 `sub_questions` |

另补强两个课程的 `COURSE_PROMPTS`：明确**判断题填「对/错」、填空题填具体内容**，
解决 LLM 把判断题答案生成为 A/B 的问题。

## 六、技术要点

| 主题 | 做法 |
|---|---|
| **题号定位** | 正则 `^(\d+)[.．、](?!\d)`（排除小数）；按行扫 PyMuPDF 的 dict 结构取每行 bbox；跳过页眉 `y<60` 与页脚 `y>780` |
| **跨页检测** | 下一题 `page == 当前题 page + 1` 即认为跨页；截当前页底部 + 下一页顶部，垂直拼接为一张图 |
| **VLM 策略** | 只对矢量绘图数 ≥3 的题用 VLM（有表格/图表的题）；**两步法**：先 VLM 描述图表 → 再纯文字调 LLM；**避免图片 + 长文本同时发**（会 400） |
| **答案质检** | 选择→`^[A-D]$`；综合→`answer=null` 且 `sub_questions` 非空；不合规标 `needs_review=true` |
| **数据结构** | 18 字段；综合题用 `sub_questions: [{label, answer}]`，与选择题的 `answer` 分离 |
| **使用方式** | `python -m course_agent.question_bank <pdf>` 单份；不带参数批量处理 |
