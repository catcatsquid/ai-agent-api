## 一、一句话

> **一个面向大学两门课（操作系统 + 计算机网络）的学习 Agent**：
> 既能回答知识点问题（RAG 问答），也能按课程/试卷组织刷题、批改、讲题，
> 还带一个知识库管理台。Agent 层有**两条实现**（LangGraph 图 / 手写循环）做对照。

**它要解决的三个真实场景**：

| 场景 | 用户说的话 | 系统要做什么 |
|---|---|---|
| 答疑 | "死锁的四个必要条件是什么？" | 检索课程资料 → 组织回答 |
| 刷题 | "我想刷计算机网络的选择题" | 列卷子 → 一组一组出题（**题图**）→ 批改 → 讲不会的题 |
| 管资料 | （管理台）导入/删除/检索 | 增量入库、按课程过滤、看统计 |

**三条数据流**：

1. **问答流**：`/qa/stream`（或 `/chat/stream`）→ 图/循环 → 调 `search_knowledge`
   → `rag_tool` 混合检索 → 按课程过滤 → 组织回答（SSE 流式）
2. **刷题流**：`/tutor/stream` 或 `/qa/stream` → `list_papers` → 学生选卷
   → `get_paper_questions`（**只给题号+知识点+题图，题干和答案故意不给**）
   → 学生发答案 → `grade_answers`（选择/判断精确判定，填空/综合由阅卷模型评分）
   → 说不会 → `explain_question`（**按需**取回题干与参考要点）→ 讲
3. **建库流**：`build_knowledge.py` → `knowledge_pipeline` 或经典加载路
   → `doc_utils` 抽取/清洗 → 切块 → embedding → ChromaDB

## 三、两条 Agent 路径（这是本项目最需要解释的一点）

同一个需求有两条实现，**各有明确分工**：

| | 路径 A：LangGraph | 路径 B：手写循环 |
|---|---|---|
| 入口 | `/qa/stream`、`/chat/stream` | `/tutor/stream` |
| 范式 | Plan-and-Execute + ReAct 两张图 | 单循环 `process_message` |
| 会话状态 | `MemorySaver` checkpoint（两图**各一份**）+ `state["session"]` 游标 | 进程内 `_SESSIONS`（3 小时 TTL） |
| 上下文治理 | 窗口 + LLM 摘要（`memory.py`） | 摘要 + **工具结果压缩** + 历史裁剪 |
| 工具数 | 10 个 | 8 个 |
| 会话守卫 | 无 | **有**（"没看到题目"重发、一次确定性纠偏） |
| 定位 | **路线内；产品主路径** | **第 9 周「手写 Agent」的实现** + 守卫更全 |

**关键：它俩共用 `quiz_service.py` 这一份业务逻辑**，各自只保留"外壳" ——
一边返回 JSON 字符串 + 显式参数，一边返回 dict + 会话游标 + `_guide`（呈现契约）。
所以维护成本不是双份。

> 为什么要有 `_guide`：只给模型"数据"，它会自己组织，组织不出来就**编**。
> 给它成品文本（`reply_text`）和"这一步只做什么"的指引，它就没有编的空间。
> 这条教训见过两次：一次是助教的"我不会"讲不了题，一次是 Plan 图**伪造题目**。

## 四、关键技术决策（每条都有取舍）

| 决策 | 选了什么 | 为什么不选另一条 |
|---|---|---|
| **防泄题** | 出题只给题号/知识点/题图；学生说不会时用 `explain_question` **按需取回** | 不是"不给模型题面"——那样它物理上讲不了题，只能说空话（踩过） |
| **呈现契约放哪** | 写进**工具返回值**（`reply_text` / `_guide`） | 不写进 system prompt：实测"枚举式格式说明"会被模型当成**许可清单**，反而拒绝合法输入（`AAAAA` 被拒） |
| **题号口径** | 一律用**题型内序号**（`section_numbers()`） | 不用题库自带的 `display_num`：它在不同题型之间重复（选择题第1题 vs 综合题第1题） |
| **歧义怎么处理** | 返回候选让模型问，**绝不猜** | 猜错会把一份答案批到另一组题上，学生看到的是"全错" |
| **L2 距离** | 换算成余弦（`1 - d²/2`）再比阈值 | 直接把距离当相似度：域外查询（d>1）会算出**负分** |
| **阈值判据** | 用**绝对**相似度（`sim`）；归一化融合分 `score` 只用于**排序** | 拿归一化分比绝对阈值：排名第一恒 ≥0.6，判据**永远不成立**（死代码） |
| **工具环上限** | `MAX_TOOL_ROUNDS = 6` + 轮数用尽时改用**不带工具**的 llm | 不设上限：实测跑到 **5004 次 LLM 调用** |
| **鉴权** | **默认拒绝 + 显式白名单**；本地默认关闭 | 逐个路由手写 `Depends`：会漏（`/qa/stream` 就漏了，而前端调的就是它） |
| **路径校验** | 放在**处理函数内部**（与鉴权解耦） | 放依赖里：关掉鉴权就一起失效了 |
| **两图会话** | **各用独立 checkpointer** + 显式存游标 | 共用一个：同 thread_id 换模式会读到对方状态，并因"孤儿 tool 消息"被接口按协议拒绝 |

## 七、技术栈

| 层 | 用了什么 |
|---|---|
| Web | FastAPI + uvicorn，SSE 流式（`StreamingResponse`）；单文件前端（内联 JS，无构建） |
| Agent | **LangGraph**（StateGraph + MemorySaver、Plan-and-Execute、ReAct）；另有一套**手写**循环 |
| LLM | 智谱 GLM-4-Flash（`llm.py` 直接 HTTP 调用 + 兼容层）、GLM-4V（题图理解）、Embedding-3（2048 维） |
| 检索 | ChromaDB（持久化，L2 空间）+ rank_bm25 混合检索 |
| 文档 | PyMuPDF / pypdf / python-docx / Pillow（切题图） |
| 工程化 | pydantic、python-dotenv、PyJWT、自研结构化日志（`contextvars` 传 trace_id） |
| 测试 | pytest（413 项）+ Node 断言（52 项，读真实页面）+ Locust 压测 |

## 九、已知限制（诚实清单）

| 限制 | 说明 |
|---|---|
| **`chapter` 不是真章节** | 元数据里它是"来源内的文件名标签"（20 个来源里 0 个有多个值），课本那 55% 是空的。**按章检索目前是假的**。真修法要在入库时保留页/章结构并**重新 embedding 4199 个分块**，评估后决定先不做 |
| **Plan 图是"简化版"规划** | 一次规划 + 批量执行，**没有 re-plan**；`route_after_executor` 用中文子串 + 长度阈值判断结果够不够 |
| **会话状态在进程内存** | 重启即丢、多 worker 不共享（两张图的 MemorySaver 与助教的 `_SESSIONS` 都是） |
| **`rag_tool` 反向依赖 `course_agent`** | 它 import 了 `course_agent.errors`/`logger`。修它只是搬文件，无行为收益，故保留并记录 |
| **无真实用户体系** | 只有一个管理密码换 JWT；无权限区分 |
| **手写循环的兼容层很薄** | `SimpleLLM` 不是真正的 LangChain `Runnable`（`config` 被丢弃 → 无 callbacks/结构化输出） |
| **第 9 周「开源阅读」没做** | 手写 Agent 那半句被助教覆盖了，但这条不算完成 |

## 十一、如果你想 30 秒讲完

> 这是一个两门大学课程的**学习 Agent**：能答疑，也能按试卷组织**刷题—批改—讲题**。
> 数据层是 4199 个分块的混合检索知识库 + 191 道结构化真题（带题图）。
> Agent 层有两条实现：LangGraph 的 Plan/ReAct 图和一套手写循环，
> 它们共用同一份业务逻辑（`quiz_service`）。
>
> 我在上面做的**最有价值的一件事**不是堆功能，而是发现了一个反直觉的现象：
> 同一个模型，裸用很灵活，套进 Agent 反而照本宣科。
> 排查下来是三个失真源 —— 信息不完备、契约冲突、状态不可见 ——
> 之后所有修复都沿着"补信息、减职责、让状态可见"走，而不是继续往 prompt 里加规则。
> 其中最深的一条是：**"工具结果要不要留在上下文里"这个设计选择，
> 直接决定了多轮会话能不能成立**（Plan 图因为丢弃它，刷题流程一度是坏的）。
