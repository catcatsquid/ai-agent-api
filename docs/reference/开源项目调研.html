二、与"知识库问答 Agent"最相关的 6 个项目

Tencent/WeKnora 2,900+ commits
企业知识库

腾讯开源的企业级知识框架。三大核心能力：①RAG 快速问答（日常查询）②ReAct Agent 自主推理（复杂问题）③Auto-Wiki 自动知识整理。支持文档摄入→语义检索→Agent推理→答案生成的完整闭环。Go 后端 + React 前端，有 Docker 一键部署。

GoReactRAGReActDocker
你选的"课程知识库问答"方向和 WeKnora 的"RAG + ReAct Agent"模式完全一致，可以参考它的 Agent 编排思路和知识库管理设计。
mhourani/ai-knowledge-agent Enterprise RAG
企业 Agentic RAG

企业级 Agentic RAG 系统：用 LangGraph + ChromaDB + Claude 构建。不是简单"检索→回答"，而是会"推理"的 RAG：①分析问题并优化搜索查询 ②向量知识库语义检索 ③评估检索结果是否足够 ④不足则自动优化查询再检索。这个"自省"机制是亮点。

LangGraphChromaDBClaudePython
LangGraph + 向量库的组合和你第4周的技术栈完全一致。重点学它的"检索结果评估→自动优化查询"节点设计，这是普通RAG和Agentic RAG的分水岭。
yikesuanlizi/Agentic Knowledge OS 12-Node Graph
知识操作系统

从文档摄入到智能问答的完整 Agentic RAG 系统。知识摄入支持 PDF/DOCX/TXT/MD，自动分块+实体抽取+元数据推断。知识编译用两阶段 LLM 生成结构化 Wiki 卡片。检索引擎：向量召回+全文检索+BM25重排+Wikilink图扩展。Agent编排：LangGraph 12个节点的复杂工作流。

LangGraphFastAPIBM25Rerank
12节点图比你目前的4节点复杂很多，但你第5-6周可以逐步往这个方向加节点。重点看它的"知识编译"概念——不是直接存原始文本，而是先LLM整理成结构化卡片再入库。
ATLAS: Academic Task & Learning Agent Educational
学术学习助手

多Agent学术辅助系统，4个专业Agent协作：Coordinator（协调）+ Planner（计划）+ Notewriter（笔记）+ Advisor（建议）。用 LangGraph 工作流编排，根据学生表现和反馈持续调整。每个Agent有专属职能，通过状态图协调。

LangGraphMulti-AgentPydantic
这是"课程/知识库问答"方向最直接的参考——4个Agent协作的架构可以作为你第5-6周从单Agent到多Agent的过渡参考。第4周先做单Agent版本，后续逐步加角色。
Chiron: Feynman Learning Agent Educational
自适应学习

基于费曼学习法的自适应学习Agent。核心流程：定义检查点→构建上下文→验证理解（70%通过率才继续）→费曼式简化讲解。整合Web搜索获取动态内容，语义分块，Embedding检索。有人机交互验证环节。

LangGraphEmbeddingsWeb Search
"理解度验证"机制很适合课程知识库场景——不仅回答问题，还验证用户是否真懂了。你可以简化这个机制：在Agent回答后加一个"生成测试题"节点。
PolicyBot AI Agent Enterprise Policy
企业政策问答

企业级文档问答系统，专门针对公司政策文档。用 RAG 技术回答关于公司政策的问题，同时也能处理通用查询。Docker部署 + Azure OpenAI + FastAPI + FAISS 向量数据库。是"政策法规→QA"垂直领域的典型范例。

FastAPIFAISSAzure OpenAIDocker

四、开源项目垂直领域选择的 5 大规律

规律 1：文档越多越杂的领域，RAG Agent 越有价值
几乎所有成功的知识库 QA 项目都选了"文档多到人读不完"的领域——企业政策、法律法规、学术文献。不是因为技术上更难，而是因为"没有 RAG 真的答不了"这个需求真实存在。
PolicyBot（公司政策）→ WeKnora（企业文档）→ EU Green Deal Bot（欧盟法规）
规律 2：垂直 > 通用——越聚焦越好做
没有项目做"万能知识库问答"。成功的项目都选了一个极窄的切入点：不是"教育问答"而是"学术课程学习规划"；不是"企业文档"而是"公司政策合规"。垂直领域越窄，知识边界越清晰，Agent 效果越好。
ATLAS（不是"教育Agent"而是"学术任务规划Agent"）→ PolicyBot（不是"企业Agent"而是"政策合规Agent"）
规律 3：知识结构决定 Agent 架构
选择领域时，先看知识本身的结构：线性教材→简单RAG够用；层次结构课程→需要多级检索+Agent路由；开放性学术文献→需要多Agent协作+质量评估。知识结构的复杂度决定了你要用多复杂的 Agent 架构。
Chiron（线性学习+验证→单Agent+检查点）→ ATLAS（多角色协作→4个专业Agent）→ Agentic Knowledge OS（复杂知识编译→12节点图）
规律 4：好领域 = 痛点真实 + 数据可得 + 效果可验证
三个条件缺一不可：①痛点真实（不是"想象出来的需求"）②数据可得（你能拿到该领域的文档/数据来做知识库）③效果可验证（问几个问题就能看出 Agent 回答得对不对）。学术领域痛点真实但数据难获取；企业政策数据好拿但痛点弱；课程领域三者全满足。
✅ 课程知识库：痛点真实（学习需要）+ 数据可得（教材PPT笔记）+ 效果可验证（问课程问题）
规律 5：面向求职——选与目标公司业务相关的领域
韶音科技是硬件+音频+算法公司，算法岗需要大量读论文。选"课程/知识库问答"方向可以，但如果能在知识库里加入论文/技术文档作为检索源，就和目标公司的实际需求产生了直接关联。
韶音科技算法岗 → 需要读论文 → Agent 能检索音频/信号处理论文 + 课程笔记 → 简历直接对口

五、对你的建议

结合你的情况（韶音科技算法岗 + 第4周 LangGraph + 已有RAG基础）

你已经选了"课程/知识库问答 Agent"，这个方向是对的。关键问题是：知识库装什么内容——这决定了你的项目在简历上的含金量。

方案 A：纯课程知识库（推荐先做）第4周
知识库内容 = 你已学课程的笔记/教材（AI Agent 开发10周路线的笔记、RAG相关知识、Prompt Engineering 等）。优势：数据你手上就有，Day 3-4 直接能接入第2周的 RAG 检索。这周就能跑通完整 Demo。
方案 B：课程 + 技术文档双知识源第5-6周
在方案A基础上，增加第二个知识源：LangGraph/LangChain 官方文档。Agent 需要判断问题属于哪个知识源，然后路由到对应检索器。这展示了多工具编排能力，也是你"多工具编排"第3周技能的升级版。
方案 C：课程 + 论文摘要知识库简历加分
知识库加入几篇音频/信号处理领域的论文摘要（和韶音科技业务相关）。Agent 能回答"课程问题"也能回答"论文问题"。面试时说"我的 Agent 能检索课程笔记和音频领域论文"，直接对口韶音科技。

建议路线：方案A（第4周跑通）→ 方案B（第5-6周升级）→ 方案C（简历定稿前加论文数据源）。渐进式增加复杂度，每一步都有可运行的 Demo。
