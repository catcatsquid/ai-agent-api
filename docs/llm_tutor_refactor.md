# 学习/复习模式重构记录（含最终结论）

> 状态：**已结束。定性：需求驱动的产品特性（不在 10 周路线的周次里），
> 同时兼做一个未完成的对照实验。**
> 结论先行：它存在的理由是"我要一个不用反复声明学习流程的学习/复习 Agent"，
> 这个理由成立且仍然有效；但它**不能算第 9 周的产出**，
> 而且它当时兼着的"对照"目的**没有达成** —— 代价是删掉了一套能用的状态机实现。
> 详细取舍见文末「最终结论」。

---

## 0. 它到底为什么存在

两个层面的动机，别混为一谈：

1. **产品动机（主要、成立）**：我作为使用者，希望这个 Agent 天生就懂我的学习/复习习惯 ——
   逐节教、小节测、错了重刷、复习优先刷错题 —— 而不用每次开对话都把这些流程再说一遍。
   这是项目的一个差异点，也命中真实使用需求。
2. **技术动机（次要、未达成）**：顺便拿它跟原来的 Python 状态机版比一比，
   验证"LLM 主导会不会更灵活"。见下面第 2 节 —— 这个对照没做完。

## 1. 背景

最初的学习模式和复习模式（`learn.py` 295 行 + `review.py` 487 行）用 Python 状态机实现：

```
新会话: 解析课程章节 → KB检索 → LLM生成大纲 → 教第1节 + 出小测题
quiz_pending: 用户提交答案 → 批改讲解
...
```

问题：用户反馈交互死板、不灵活。例如刷题时用户说「换一套卷子」会被当成答案批改
（`review.py` 里靠 `_is_quiz_answer(text)` 这种**硬编码意图判断**分流，
一旦用户的说法不在预期内就分流错）。

## 2. 重构方向：LLM 主导对话

让 LLM 主导对话，通过 Function Calling 调用工具（知识库检索、习题库、批改等），
把"该做什么"交给模型判断，而不是用 Python 写死状态流转。

### 方案 A：手写工具调用循环（`tutor_agent.py`）——**已实现**

- 自己写 `_stream_round` 调智谱 API，解析 SSE 增量与 `tool_calls` 分片
- 主循环 `process_message`：LLM → 看 tool_calls → 执行工具 → 结果回传 → 再调 LLM → 无工具则输出
- 最多 6 轮工具调用，防止死循环
- 会话状态在进程内 `_SESSIONS` 字典（带 TTL 回收）

### 方案 B：LangGraph 架构（`lg_tutor.py`）——**从未实现**

原计划用 LangGraph 的 StateGraph + ToolNode 复用现有 `graph.py` 的架构风格，
以便和方案 A 做真正的对照。

**这个文件不存在。** 所以本记录里原本写的「对比两种实现的差异」这件事
**从头到尾没有发生**——只有一份实现，没有对照。

## 3. 实际发生了什么（比计划更重要）

对照没做成，但方案 A **已经取代了状态机**：

- `learn.py` / `review.py` 已删除（连带的 `chapter_utils.py` 也失去了全部调用方，一并删除）
- 删除是**单向的**：状态机版那 782 行里已经调通的流程（逐节教学、小测批改、
  章节总复习、错题重刷）在助教里并没有一一对应地重建

也就是说，"只用来对比"这个说法与实际结果不符：对比的一半缺失，
被比较的对象却已经被移除了。

## 4. 「LLM 主导更灵活」这个假设的实测结论

当初的直觉是"LLM 主导会更灵活"。现在有数据了，结论是**部分成立，但代价被低估了**。

### 4.1 灵活性没有换来正确性

两个模式（LangGraph 的 `知识寻回BOT` 与手写的 `LLM助教`）现在共用
`course_agent/qbank.py`，所以**分组出题、不泄题、按题型精确批改的行为完全一致**。
差异只在编排层，不在能力层。

### 4.2 自由度需要靠"把结构补回去"来兜底

助教这一路修下来，几乎每一条新增约束都是在把框架/状态机本来能结构性保证的东西重新装回去：

| 后来补上的约束 | 它解决什么 | 状态机里对应的东西 |
|---|---|---|
| `reply_text` 成品文本 | 模型转录 8 份卷子时漏了 3 份 | 列表本来就是代码拼的字符串 |
| 课程守卫 | 模型在"我想刷题"时自己填 `course`，藏了一半题库 | 课程是路由参数 |
| `prepare_custom_quiz` + 范围守卫 | 模型拿计网题冒充死锁题 | —— |
| 答案格式契约 | 模型把 `AAAAA` 当成"你没提交答案" | `_is_quiz_answer`（但过于死板） |
| `explain_question` | 模型手里没题目，讲不了题 | 状态机直接持有题面 |

有意思的是最后两行：`_is_quiz_answer` 就是你当初嫌弃的"写得太死"，
而助教最后也长出了 `_wants_custom_quiz()` + 答案格式契约 —— **同一个问题的弱化版**。
两者不是"死板 vs 灵活"，而是同一条光谱上的两个点。

### 4.3 手写循环有约 330 行（≈28%）在重造框架白给的东西

```
_stream_round     61 行   SSE 解析 + tool_call 分片拼装
process_message  116 行   主循环
_chat_json        31 行   非流式调用 + JSON 解析 + 429 重试
_post_stream      24 行   带退避的流式请求
_new_session/get_session/sweep_sessions  27 行   会话与 TTL
_compact_tools/_trim_history             30 行   上下文治理
_tool_label/_tool_summary                40 行   前端事件
------------------------------------------------
合计约 329 行 / 全文件 1197 行
```

LangGraph 的 `StateGraph` + checkpointer + `ToolNode` 直接提供这些。

## 5. 最终结论

1. **它不在 10 周路线的周次里，但这不是"跑题"。**
   它的定位是**需求驱动的产品特性** —— 我要一个天生懂我学习/复习习惯、
   不用每次重新声明流程的 Agent。这个动机独立于路线成立。
   路线里第 9 周是「开源阅读 + 手写 Agent」、第 10 周是「面试冲刺」，
   从来没有"对话式刷题重构"这一周。之前 README 的「已完成」表里被填了一行
   `第9周 | 对话式刷题重构`，那是往回填路线以贴合已完成的工作，已改正。

2. **它兼着的对照目的没达成。** 方案 B 缺失，所以结论其实是
   "单方面替换"，不是"对比后择优"。这一点要在文档里说清楚，
   免得后人以为这里做过严谨比较。

3. **它不能算第 9 周的产出。** `tutor_agent.py` 就是一个手写 Agent
   （自己解析 SSE 增量、自己拼 `tool_calls`、自己管会话与上下文压缩）。
   但它不是按第 9 周计划做的，也没有配套的开源阅读，所以第 9 周仍算**未完成**。

4. **保留并明确定位**：代码可用（见下面第 6 节），README 里列在
   「路线外（不计入周次）」并注明性质是产品特性而非路线任务。

5. **关于面试怎么讲**：两条线可以分开讲，别混在一起说成"我做了个技术对比"。

   **讲产品**（这是更强的一条）：
   > 我做了一个学习/复习 Agent，出发点是"我不想每次开对话都重新声明我的学习流程"。
   > 它上线后我自己天天用，然后按真实使用的吐槽迭代了 5 轮：
   > 说"我不会"时它讲不了题（因为防泄题把题面也从模型手里拿走了）→ 加了按需取题的
   > explain_question；答 "AAAAA" 认不出来 → 放宽解析并加了"格式判断交给工具"的契约；
   > 说"继续刷题"却不出题 → 把清单做成成品文本 reply_text，并在循环里加了一次确定性纠偏。

   **讲技术取舍**：
   > 为了验证"LLM 主导是不是比状态机灵活"，我手写了一个 tool-calling 循环替换掉原来的状态机。
   > 做完发现：灵活性确实有，但正确性一点没多赚；为了保证可靠，我得把框架白送的
   > 会话管理、流式拼装、上下文治理重写一遍（约占 28% 代码量），又要用
   > "工具返回值承载呈现契约"的方式把约束一条条补回来，
   > 最后长出来的东西和当初被我嫌弃的状态机是同一类设计。

   注意第 9 周**仍然要单独准备**：面试官问"手写 Agent"时，能白板写出的应该是
   主循环 + 流式 tool_calls 拼装 + 会话/上下文治理，而不是"我会调工具"
   （调工具在主 BOT 里也是手写的：`llm.py` 直接用 requests 发 tools 请求）。

## 6. 当前可用性

助教模式在聊天页「LLM助教」按钮下可用。它现在的实际能力：

| 工具 | 作用 |
|------|------|
| `list_papers` | 按课程列试卷（默认两门课都列） |
| `get_paper_questions` | 分组出题：选择/填空/判断 5 题一组，综合题 1 题一组 |
| `explain_question` | 取题面 + 参考答案 + 参考要点，用于讲题 |
| `prepare_custom_quiz` | 取"临时出题"的素材（题目由模型自己写） |
| `grade_answers` | 批改（选择/判断精确判定，填空/综合按参考要点评分） |
| `search_knowledge_base` | 知识库检索，可按课程过滤 |
| `get_practice_stats` / `record_practice` | 练习次数统计 |
