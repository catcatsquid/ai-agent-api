# 技术笔记：两条 Agent 路径——如何对比、如何追平、各自定位

> 起因：我在认真考虑「LLM 助教（手写循环）还有没有必要留着」。
> 结论：**留着，而且理由从"历史包袱"变成了"对照实验"**。
> 但真正有价值的是中间那段：**同题对比 → 发现 BOT 吃亏 → 定位三处落差 → 五处修复 → 追平**，
> 以及追平过程中暴露出来的**代价结构**。

---

## 一、先厘清：两条路径各自"遵照什么"建起来的

这是面试很容易被追问的点，而且答案不是一句话。

### BOT（LangGraph）—— 严格按十周路线

逐周都能在代码里找到证据（`debug/verify_roadmap_coverage.py`）：

| 周 | 路线要求 | 代码证据 |
|---|---|---|
| 1 | FastAPI + SSE 流式 | `server.py`、`sse_content_event` |
| 2 | RAG + 向量搜索 | `rag_tool.py` + ChromaDB |
| 3 | ReAct 多工具 Agent（工具编排 + Function Calling） | `archive/week1-week3/week3-react-agent`（手写版，已归档） |
| 4 | LangGraph ReAct + RAG 集成 + 知识库流水线 + 守卫节点 + B3 测试 | `graph.py`/`nodes.py`、`knowledge_pipeline/`、`web_search_fallback` |
| 5 | Web 搜索 + Plan-and-Execute + 多轮持久化 | `web_search`、`planner_node`、`MemorySaver` |
| 6 | 双模式流 + 端到端测试 + 知识库盲区修复 | `react_graph`、`RELEVANCE_THRESHOLD` 修复 |
| 7 | 全局异常 + 结构化日志 + trace_id + 配置规范化 | `errors.py`、`logger.py`、`config.py` |
| 8 | 向量+BM25 融合 + LLM Rerank + 查询改写 + Docker + 压测 + 管理界面 + 题库 | `_hybrid_search`、`_llm_rewrite_query`、`Dockerfile`、`locustfile.py`、`kb.html`、`qbank.py` |
| 9 | 开源阅读 + 手写 Agent | 手写 Agent ✅（见下）；**开源阅读 ❌ 没做** |
| 10 | 面试冲刺 | `docs/面试自测清单.md` |

**超出路线的部分**（repo 里有、路线表没列）：鉴权与默认拒绝守卫、限流/请求日志中间件、
CI、前端行为断言、`quiz_service`（架构去重）、`doc_utils`（断循环依赖）。
—— 这些是后来按真实问题补的，不属于路线，面试要**如实区分**。

### LLM 助教（手写循环）—— 需求驱动 + 一个**没做完**的对照实验

它**不是**按某一周做的。来源见 `docs/llm_tutor_refactor.md`：

1. **产品动机（成立）**：我作为使用者，希望这个 Agent 天生就懂我的学习/复习习惯
   （逐节教、小节测、错了重刷），不用每次开对话再把流程声明一遍。
2. **技术动机（未达成）**：原本想拿它跟**原来的 Python 状态机版**比一比
   （`learn.py` + `review.py`，共约 900 行），验证"LLM 主导会不会更灵活"。
   状态机的问题很具体：靠 `_is_quiz_answer(text)` 这类**硬编码意图判断**分流，
   用户说「换一套卷子」会被当成答案批改。
   计划里的另一半（LangGraph 版助教 `lg_tutor.py`）**从未实现**，
   所以那个 A/B 对照**从头到尾没发生**。

> ⭐ **一个值得点出的巧合**：现在做的这个 BOT vs 助教对比，
> **正是当初那个没做成的对照** —— 只不过对手从"状态机"换成了"路线内的 LangGraph Agent"。
> 也就是说，这次对比补上了一个搁置的缺口。

另外两个诚实细节：
- `tutor_agent.py` 在 10-03 之前**从未进过 git**（一直是未跟踪文件），
  09-30 提交的是状态机版；状态机版在 10-03 被删除、助教才第一次被跟踪。
- 助教**不能算第 9 周产出** —— 第 9 周要求「开源阅读 + 手写 Agent」，
  后半句沾边，前半句没有配套产物（全项目搜不到任何"读框架源码"的东西）。

## 二、对比方法（以及我的测量工具错了两次）

### 方法

同一段学生脚本、同样 5 个场景，两个运行面各跑一遍，判据全部是
**学生视角能感知到的**（不是"有没有调工具"这种实现视角）：

```
我要复习操作系统 → 我答一下：1.B 2.D 3.对 4.银行家算法 → 第二题我没懂，换个讲法
→ 现在换计算机网络，我要复习传输层 → 那刷几道传输层的题吧
```

信号分"好/坏"两类，坏的权重更高（学生更在意踩坑）。跑多轮取一致性。

### ⚠️ 我的探针错了两次，值得单独记

第一轮我得出过「助教把学习流程弄坏了」的结论，**那是错的**，因为：

1. **发错了字段名**：助教接口要 `session_id`，我发的是 `thread_id` → 被忽略
   → **每一轮都是新会话、状态全丢**。我看到的"没有记忆"是探针造出来的。
2. **抓错了事件名**：助教发 `{"type":"tool"}`，我只抓 `{"type":"node"}`
   → 误判"工具根本没被调用"。

改对之后，真实表现**本来就比我说得好**：学生交小测答案时助教**不调工具、自己逐题批**。

> **教训：测一个 Agent 之前，先验证你的测量工具。**
> 具体做法：① 先单独确认状态能跨轮（打印一次会话状态）；
> ② 判据不要依赖"实现细节"（工具名/事件名），要依赖"用户能看到的结果"。

判据本身也修过一次：一开始用"回复里有没有文件名"判断"读对了章"，
结果被"工具提示里带了文件名"误导；改成"有没有该章的内容关键词"才准。

## 三、第一轮：BOT 明显吃亏

```
合计        BOT 好17 / 坏16   |   助教 好27 / 坏5
  开始复习      BOT 6/3   助教 9/0
  说没听懂      BOT 2/4   助教 6/0
  按知识点刷题   BOT 0/5   助教 3/0
  交小测答案    BOT 3/3   助教 3/2
  换一门课      BOT 6/1   助教 6/3
```

典型失败：
- 「我要复习操作系统」→ 讲了，但**不说"本节结束"、不出小测**
- 「我答一下…」→ **"请提供具体的问题和选项"**（手里没有小测题，批不了）
- 「第二题没懂」→ **自己编了一道题**（"假设我们讨论的是…以下是一个可能的问题"）
- 「刷几道传输层的题」→ **只给试卷菜单**（"请告诉我选哪一份"）

## 四、三处根因（关键的那一处不是范式问题）

### 根因 1：⭐ 状态注入放错了位置

```python
# BOT
planner_node     里出现 study: True     ← 学习书签只喂给了「规划器」
synthesizer_node 里出现 study: False    ← 「写回答的模型」看不到

# 助教
_system_prompt_for(session) → messages[0]   ← 写回答的模型直接看得到
```

**"本节结束 / 出小测 / 小测由你自己批"这些是写给"写回答的模型"的契约**，
BOT 却只把它交给了规划器。尤其「学生交小测答案」那一轮**一个工具都不会调**
（走 `CHITCHAT_PROMPT`），所以那段契约在 BOT 侧根本到不了模型手里。

### 根因 2：两条守卫只在助教有

- **"没看到题目" → 确定性重发**（学生报过这个 bug）
- **历史裁剪 + 工具结果压缩**（BOT 的 `MemorySaver` 原来**没有任何上限**，审查文档 F2）

### 根因 3：planner 缺"看宾语"的路由规则

- 「刷几道**传输层**的题」= 按知识点练 → 该用 `prepare_custom_quiz`；
  而 planner 的规则 1（"刷题 → list_papers"）先命中，于是永远给菜单。
  题库没有按知识点组卷，**给菜单等于没满足需求**。
- 「没听懂/换个讲法」→ 该 `read_section` 重取原文；planner 没想到。

## 五、五处修复（每处都有实测数据支撑）

| # | 修什么 | 怎么修 | 效果 |
|---|---|---|---|
| 1 | synthesizer 看不到会话状态 | 新增 `_session_block()`，同时拼进 `SYNTHESIZER_PROMPT` 与 `CHITCHAT_PROMPT` | **没有直接拉升分数** —— 它是前置条件（见下方说明） |
| 2 | 没有重发守卫 | planner 里加**确定性覆盖**：学生说"没看到题目"且有当前组 → 强制重发那一组（覆盖原计划） | 「没看到题目」不再只得到道歉 |
| 3 | 历史无上限 | 按 **user 消息边界**裁剪 + 较早的工具结果正文换占位符；裁剪保证 assistant(tool_calls) 与 tool 成对（不留孤儿） | F2 缓解 |
| 4 | 按知识点刷题走错 | planner 规则补"看宾语"：按知识点的练习 → `prepare_custom_quiz` | 0/5 → 2/0 |
| 5 | 讲课中交答案去调题库 | 新增 `_looks_like_quiz_answer()`；讲课中且无当前试卷时**这一轮不规划任何工具** | 3/3 → 2/0 |

> ⚠️ **一个值得注意的细节**：最有洞察力的那处修复（#1 状态注入位置）**没有直接拉升分数**。
> 它只是让契约"能到达"写回答的模型；真正让分数动的是 #4 和 #5 这类**路由与守卫**。
> 也就是说：**"找到根因"和"指标改善"不是同一件事，别用指标反过来否定根因判断。**
> （#1 的价值在后面才显出来：没有它，#5 那条守卫即使拦住了题库调用，
> 模型手里也没有"小测由你自己批"的契约。）

**修复过程中的数据变化**（每轮 = 5 个学生场景）：

```
第一轮（已含 #1，但缺路由规则与守卫）   BOT 好17 / 坏16    助教 好27 / 坏5
第二轮（再补 #4 路由规则）             BOT 好15 / 坏8     助教 好18 / 坏2   ← "说没听懂"已拉平 4/0
第三轮（再补 #2 #3 #5 三条守卫）        BOT 好16 / 坏3     助教 好18 / 坏2   ← 基本持平
```

第三轮逐项：交小测答案 2/0＝2/0 ✅、说没听懂 4/0＝4/0 ✅、按知识点刷题 2/0＝2/0 ✅、
换一门课 4/1≈4/2、**开始复习 4/2 < 6/0**（BOT 说"本节结束"仍不稳定）。
耗时：BOT 289.7s vs 助教 250.2s。

## 六、⭐ 代价结构：这才是决策的关键输入

**BOT 不是"做不到"，而是每加一种行为契约，都要想清楚两件事**：
它该注入**哪个节点**（planner 还是 synthesizer？），以及该写**哪条路由规则**。
而手写循环把这些压在同一条链路上，状态直接进回答阶段，"自然地就有"。

> **BOT 的灵活性来自分工，成本也来自分工。**

这条在本次会话里被验证了**三次**：

1. 刷题工具：两个运行面各写一份 → 真实分叉（一边缺 `basis_warning`、题号口径也不同）→ 合并到 `quiz_service`
2. 学习/复习工具：我只做了 BOT 侧，**漏了助教侧** → 加 `tests/test_surface_parity.py` 强制对齐
3. 行为契约：`_guide` 谁看得见？ → 就是我这次踩的坑

所以"两条都留"的**真实成本**是：新能力要么实现两遍，要么用共享层 + 一致性测试把它钉住。

## 七、两条路径的机制差异清单（面试"为什么这么选"的素材）

| 维度 | BOT（LangGraph） | 助教（手写循环） | 为什么会有这个差异 / 各自适合什么 |
|---|---|---|---|
| 状态注入 | 分节点（planner 看得到、synthesizer 原本看不到） | 直接进 system prompt | 分工带来灵活性，也带来"注错了没人发现"的风险 |
| 跨轮状态 | `AgentState["session"]`，由 executor **从工具结果里抽** | handler 里**直接写** session | 抽取式解耦但要解析约定；直写简单但耦合 |
| 工具路由 | planner 出 JSON 计划 + 代码守卫 | 模型每轮自己选 + 代码守卫 | 计划式可一次规划多步；单循环更贴上下文 |
| 上下文治理 | LLM 摘要压缩（摊还缓存） | 窗口 + 工具结果压缩 + 历史裁剪 | 摘要省 token 但引入额外 LLM 调用；压缩直接但粗暴 |
| 流式 | 框架 `astream` + 统一事件函数 | 自己拼 `tool_calls` 分片 | 手写那套**能看清协议细节**，框架那套代码少 |
| 会话生命周期 | MemorySaver（原来无上限） | TTL 3 小时回收 | 各有取舍，现在 BOT 也加了裁剪 |
| 失败纠偏 | 代码守卫（重发/小测答案） | 代码守卫 + **一次 nudge** | 守卫式比提示词可靠（本次实测三次升级才治住） |
| 定位 | 路线内、产品主路径 | 进阶尝试、对照 | 见下 |

## 八、结论与定位

**两条都留。** 理由不是"历史包袱"，而是：

1. **BOT = 路线内打基础**：十周路线每个知识点的落点，能说清"这是第几周学的什么"。
2. **助教 = 进阶尝试不同方法**：它刻意用了很多 BOT 之外的做法
   （自己拼流式 tool_call、状态直写、TTL 回收、nudge 纠偏），
   于是天然构成一个**"同题不同实现"的对照**。
3. 面试时的价值：**"为什么选这个方法而不选那个"** 只能靠对照回答。
   一句"我在同一个需求上写了两套实现并做了同题对比"，
   比"我用过 LangGraph"强得多。

**但要如实说明三条**：
- 两条路径**能力已等价**（16/3 vs 18/2），所以"留两条"的收益是**对照与学习**，不是功能覆盖；
- 助教**不是路线内产出**，也不能算第 9 周（第 9 周的"开源阅读"确实没做）；
- 保留两条的真实代价是"新能力要写两遍或用共享层钉住"，这个代价我已经用
  `tests/test_surface_parity.py` 显式化了 —— **代价可见，才是可控的**。

## 九、可复用的四条

1. **测 Agent 之前先验证测量工具**：字段名、事件名、判据，任一个错都会让你得出错误结论
   （我两次误判都源于此）。
2. **判据要放在"用户能感知的结果"上**，不要放在实现细节（工具名/节点名）上。
3. **想在框架里加行为契约，先问"这个契约该给哪个节点"** ——
   给错了节点，再好的契约也不生效（本次最贵的一课）。
4. **"提示词写不要用"通常不够**：本次要治好"讲课中跑去做题库批改"，
   是三级升级 —— 提示词（不跟）→ 工具入口守卫（还不跟）→ 干脆不提供这些工具。
