## 一、刷题流程的缺陷（本次核心）

### 1.1【严重】题号解析取到"年份"，批改成错题

**位置**：`course_agent/tutor_agent.py`（旧 `_grade_answers`）、`course_agent/tools.py:167,209`

```python
def _qnum(q):
    m = re.search(r"(\d+)", q.get("qid", ""))   # qid = "2019网模拟_Q1"
    return int(m.group(1)) if m else 999        # → 2019，不是 1
```

6 份试卷里有 4 份（2019网模拟、2024OS、2025OS、2026OS）**所有题的 `_qnum` 都等于年份**。

**实测证据**（`debug/verify_grading.py`，试卷 `2019秋本部计算机网络模拟题`）：

```
提交 "3.C 4.D 5.A"
  期望：只批改第 3/4/5 题
  实际：判给 2019网模拟_Q1(标准D) / Q2(标准B) / Q3(标准D) —— 按字母顺序套到了前三题
```

**修复**：
- 题号一律用结构化字段，绝不从 `qid` 里猜；
- 新增 `qbank.section_numbers()`，按"题型内第几题"编号。

为什么不用题库自带的 `display_num` / `q_num`：**源数据本身不可靠**——

```
2019秋本部计算机网络期末考试回忆版：
  选择题 q_num=2..10  display_num=13..21、47   ← 甚至出现 q_num=4.1
  display_num=1 同时属于「填空题」和「综合题」
2019秋本部计算机网络模拟题：
  display_num=1 同时属于「选择题/填空题/判断题/综合题」共 4 道不同的题
```

用 `display_num` 查表会把「1.D」判到综合题上，并把综合题的参考答案整段泄给学生（实测发生过）。

### 1.2【严重】判断题答案一道都批不了

**位置**：旧 `_grade_answers` 的 `pattern_num` 正则

```python
r'(?:第)?(\d+)[题选.\s、]*([A-Da-d对对错错正确错误√×✓✗]+)'
```

匹配到 `1.对` 之后，只在 `choice_qs`（选择题）里按题号找 —— 判断题不在其中，永远匹配不上。
随后落到"整段塞给第一道非选择题"的兜底，把整句话当成某一道填空题的答案。

**实测**：提交全对的 `1.对 2.错 3.对 4.错 5.对` → 批改 1 题（且是填空题 F1），准确率 0/1。

**修复**：按题型分段解析，判断题做 `对/错/正确/错误/√/×/T/F` 归一化。

### 1.3【严重】"ABCDA" 被去重成 "ABCD"

**位置**：旧 `normalize_choice` 用 `"".join(sorted(set(...)))`。单题答案去重是对的，
但拿它解析"一题一个字母"的连写作答就丢了信息。

**修复**：拆成两个函数 —— `normalize_choice`（单题，去重排序）和
`letters_in_order`（连写，保序不去重）。

### 1.4【严重】带解释的句子被拆成多个答案

**位置**：旧策略2 `re.sub(r'[^A-Da-d]', '', user_text)`

**实测**：`第1题我选C，因为A和B都不对` → 拆成 `C/A/B`，套到前三题上。

**修复**：只有**全程无中文**时才按纯字母串解析；中文语境下只认紧跟在
`选/答案/是` 后面的字母（`extract_choice`）。

### 1.5【严重】出题接口泄题 + 上下文爆炸

**位置**：旧 `_get_paper_questions`

```python
item = {..., "text": q.get("text",""), "answer": q.get("answer","")}   # 答案一起返回
```

- 整卷答案进入模型上下文 → 模型随时可能提前报答案（prompt 里说"不要"并不可靠）；
- 一次调用返回整卷：实测单次工具结果 **15731 字符 ≈ 7.8k tokens**，
  连续做几组题就会顶爆上下文窗口（`_sessions` 里的历史只增不减）。

**修复**：
- 出题接口只返回 `{no, type, topic, image_url}`，**题干和答案根本不进上下文**；
- 批改时由 `qbank.build_llm_basis()` 在服务端取答案；
- 新增上下文治理：旧工具结果压缩 + 按 user 边界裁剪历史（保证 tool 配对完整）。

### 1.6【严重】分组规则靠 prompt"求"模型遵守

旧 `SYSTEM_PROMPT` 里是一整块 `⚠️ 刷题铁则 / 违反任何一条都是严重错误 /
绝对不能…`，还把"判断题 1 道一组"写成了与你预期不符的规则
（你要的是**选择/填空/判断都 5 题一组**，综合题 1 题一组）。

**修复（这也是你关心的"不能把 prompt 写死"）**：把结构约束**下沉到工具返回值**——

- 一组的题量由 `qbank.get_group()` 决定，模型拿到几条就只能展示几条；
- 工具结果带 `_render_example`，模型照抄格式即可；
- 工具结果带 `_guide`，说明"这一步怎么呈现、下一步能做什么"。

于是 system prompt 从 57 行的"铁则清单"缩到 **22 行的角色说明**，
并且测试里加了断言防止它再退化成硬规则：

```python
def test_prompt_has_no_rigid_rule_block():
    for banned in ["铁则", "绝对不能", "必须调用", "违反任何一条", "⚠️"]:
        assert banned not in tutor_agent.SYSTEM_PROMPT
    assert len(tutor_agent.SYSTEM_PROMPT) < 1200
```

### 1.7【严重】题库漏了 66 题（含最大的计网真题）

**位置**：旧代码硬读 `data/question_bank/question_bank.json`

该文件由 `question_bank.py:build_all()` 生成，而 `build_all` 只遍历
`data/{课程}/往年题/*.pdf` —— 这两份卷子没有对应的 PDF，于是**永远进不了合并文件**：

| 文件 | 题数 | 是否在合并文件里 |
|------|------|------------------|
| `questions_2019秋本部计算机网络期末考试回忆版.json` | 50 | 否（漏） |
| `questions_2018秋操作系统期末试题回忆版_WuuTang.json` | 16 | 否（漏） |
| 其余 6 份 | 125 | 是 |

结果：README 写 224 题，实际只能看到 125 题，**计网只有 47 题可见（2 份卷子）**，
而 2019 那份 50 题的真题完全刷不到。

**修复**：新增 `course_agent/qbank.py` 作为唯一题库入口，扫描
`questions_*.json` + `question_bank.json` 并按 `(source, qid)` 去重合并 → **191 题**。
新增试卷只要放进目录就自动生效，不再依赖某个生成脚本。

### 1.8【严重】"另外出题"被答成"继续翻题库"，且内容张冠李戴

**实测（修复前）**：

```
【学生】不想做这套了，帮我针对死锁这个知识点另外出几道题
【BOT】🔧 出题：2019秋本部计算机网络模拟题  → get_paper_questions
       好的，这里是关于死锁知识点的几道选择题：
       1. 死锁的定义：进程间因竞争资源而造成的一种相互等待的现象。
          ![题目](/qb_images/2019秋本部计算机网络模拟题_Q1_p2.png)     ← 其实是计网题
       2. 产生死锁的四个必要条件：...
```

只加"工具描述里提醒"不够（实测模型照样调错工具），于是做了两件事：

1. **新增 `prepare_custom_quiz` 工具**：按课程/章节/知识点检索课程材料并返回，
   题目由模型自己写，`_guide` 明确要求"不要调用题库工具、不要说成真题"。
   这让"额外出题"成为一个**正式能力**，模型有正确落点就不会去翻题库。
2. **`get_paper_questions` 加范围守卫**：学生这句是在要新题时（`_wants_custom_quiz`），
   直接拒绝出题库题并指路 `prepare_custom_quiz`。

**修复后实测**：走了 `prepare_custom_quiz`，自己写出 5 道死锁选择题，无题库图片、无错误出处。

顺带修掉一个串味问题：学生在做计网时突然要"死锁"的题，`prepare_custom_quiz`
会把课程标签降级为"未指定"，避免模型写出"在计算机网络中，以下哪种情况会导致死锁"。

### 1.9【中等】卷名模糊匹配过松，会静默换成别的卷子

模型编了个不存在的卷名 `2026春计算机网络模拟题`，模糊匹配按字符重合度
**静默命中**了 `2019秋本部计算机网络模拟题`，把学生带到了他没选的卷子上。

**修复**：加年份守卫（年份对不上直接不算命中）+ 子序列匹配（支持"2019网期末"这类简称）+
相似度阈值，命中不唯一时返回候选让学生确认。

### 1.10【严重】"我想刷题"只列一门课，题库被模型藏了一半

即使工具正确返回了两门课的 8 份卷子，模型在转录时也**只把操作系统那 5 份写进回复**
（实测：工具结果 `total_papers: 8`，回复里却完全没有"计算机网络"）。
另外模型还爱在没指定课程时自己填 `course` 参数。

这都是"让模型自己组装"带来的不确定性。两处结构性处理：

1. **工具直接给出排好版的清单**（`_render_example`），模型照抄即可 ——
   与 1.6 里出题的做法一致。改为照抄后，回复稳定包含两门课全部 8 份卷子。
2. **`list_papers` 加课程守卫**：只有当学生这句话里**确实提到了课程名**时，
   才真的按课程过滤；否则忽略模型填的 `course` 并回报
   `ignored_course_filter`，避免模型随手隐藏一半题库。

这两处都不是在写死对话流程 —— 它们只在"模型的选择会违背明确需求"时兜底，
学生说"我只想刷计算机网络"时过滤照常生效（有测试覆盖）。

### 1.11【中等】会话状态与流式输出的其它问题

| 问题 | 修复 |
|------|------|
| `_sessions` 无上限、无过期、进程内不持久 | 加 TTL 回收（3 小时） |
| 学生说"下一组"时模型得自己记进度 | 会话内记 `last_group`，不传 `group_index` 自动续下一组 |
| `_stream_final_answer` 是假的：拿到完整回答后按字符 `sleep(0.01)` 假装流式，2000 字要等 20 秒 | 改成真实流式（解析 SSE 的 `delta.content` 与 `tool_calls` 分片） |
| 模型先流出一段"前言"再决定调工具，前端已经显示了前言，之后又重来一遍 | 新增 `discard` 事件，前端清空气泡 |
| 工具轮数用尽时回一句干巴巴的兜底"我需要再想想" | 追加一次不带 tools 的收尾请求，正常作答 |
| 工具调用出错直接抛异常 | 捕获后作为工具结果回传，模型可自行调整 |

### 1.12【严重】"按课程检索"其实没有过滤效果，话题串味

修 1.12 时踩出来的：`prepare_custom_quiz` 需要判断"这个话题是否属于当前课程"，
最初的写法是"课程过滤后结果为空 → 说明不属于"。**这个判据是错的**：

```
kb.search() 对非空知识库永远返回 top_k 条 —— 它按距离排序，不会因为都不相关就返回空
```

所以按课程过滤**总能"命中"**。实测表现：学生在做计网时问「死锁」，
按计网源过滤照样返回网络层/应用层材料，`course_confirmed` 为真，
于是模型写出"在计算机网络中，以下哪种情况会导致死锁？"，甚至直接把
"请根据这些材料，针对死锁知识点，现场出5道选择题"当成答案复述出来。

**修复**：抽 `_search_with_course(kb, query, course)`，用**绝对相似度**
（`config.RELEVANCE_THRESHOLD`）判断是否真的命中：
课程过滤后最高分 < 0.55 就退回全库，并明确告知调用方课程标签作废。
`search_knowledge_base` 和 `prepare_custom_quiz` 都改用它（同一个坑两处都有）。

**验证**（`tests/test_tutor_agent.py`）：

```
话题属于该课程（sim 0.82）→ 保留课程标签、note 为空
话题不属于该课程（过滤后 sim 0.21，全库 0.81）→ 退回全库、note 提示、素材是死锁
```

### 1.13【中等】整份卷子清单被模型"选择性转录"

工具已正确返回两门课 8 份卷子（`total_papers: 8`），模型却只把操作系统那 5 份
写进回复 —— 而且**时好时坏**（同一句"我想刷题"，两次跑一次对一次错）。

这是"让模型自己组装长清单"的固有不稳定性。处理办法是把清单做成
**可以直接发出去的成品文本** `reply_text`（字段名比 `_render_example` 更明确），
`_guide` 改为"reply_text 就是这一步要发给学生的话"，并明确"不要删掉任何一份卷子"。

**验证**：连续两次完整 e2e，`回复里含两门课` 均为 True（修复前为 False）。

> 这一条和 1.10 是同一类问题的两个面：**能用代码定稿的内容就不要交给模型转述**。
> 注意这仍然不是"写死对话流程" —— 模型依旧可以加自己的语气、可以偏离、
> 可以按学生意愿只列一门课；约束只作用在"别把已确定的清单漏掉"这一点上。

### 1.14【严重】说「我不会」时 BOT 讲不了题——因为模型手里根本没有题目

**用户实测反馈**：说"我不会"以后，BOT 只会说些"请仔细阅读题目""祝你好运"之类的话，
或者干脆只丢一个答案不给解析。

**根因是设计上的**：1.5 节为了防泄题，把 `text`（题干）和 `answer`（答案）
从出题接口里彻底拿掉了。学生做题时这样很好，但**学生卡住要讲解时，模型手里
既没有题干也没有答案，物理上讲不了题**。复现时模型自己就把实话说出来了：

```
【学生】我不会，这题怎么写？
【BOT】(工具: [])                       ← 没调任何工具
这是一道关于网络性能的选择题，具体题干和选项我无法提供。
请您仔细阅读题目，根据自己的理解选择最合适的答案。
……（然后泛泛讲了一通"网络性能包括…"）希望这些信息能对您有所帮助。祝您好运！
```

**修复**（还是"把能力做成工具"的思路，而不是写死"如果学生说不会就…"）：
- 新增 **`explain_question`** 工具：按需取回**题面 + 参考答案 + 参考要点 + 小问答案**，
  并带 `_guide` 规定讲解结构：① 考点一句话 → ② 正确答案为什么对（推导别跳步）→
  ③ 其他选项/常见错法错在哪 → ④ 一句话记忆点；并明确"不要只丢答案、不要空泛鼓励"。
- `get_paper_questions` 的 `_guide` 里点明"学生说不会就用 explain_question"；
- 批改结果里**答错的题带上 `reference_points`**，否则模型只有一句"正确答案是 B"可讲，
  照样给不出解析；`grade_answers` 的 `_guide` 也要求"只说正确答案等于没讲"。
- SYSTEM_PROMPT 增加一条**能力说明**（不是流程铁律）：
  "学生说不会时他是真的要你教，先用 explain_question 取题面再一步步讲清楚"。

**修复后实测**：

```
【学生】我不会，这道题怎么写？
【BOT】🔧 取题面讲解：[1] → explain_question
这道题考查的是网络性能中的时延带宽积。首先要知道公式：带宽(bps) × 信号往返时间(s)。
10Mbps = 10,000,000bps，20ms = 0.02s，所以 10,000,000 × 0.02 = 200,000bps，
正确答案是 D。其他选项的错误原因：A 换错了单位… B 数值错… C 单位和数值都错…
记忆点：时延带宽积 = 带宽(bps) × 信号往返时间(s)。
```

### 1.15【严重】答案格式写得太死：「AAAAA」这类很自然的写法识别不了

**用户实测反馈**：给选择题答案时"AAAAA 这样的它就识别不了了"。

复现发现**解析层其实能处理 AAAAA**，真正的问题有两层：

**（a）模型会先把学生挡回去。** 学生发 "AAAAA"，模型不调 `grade_answers`，
直接回一句"看起来您没有提交答案，请完成题目后再次发送答案"。
根因是我把"格式判断"留给了模型，而它按"要写成 1.A 2.B 才算答案"的直觉行事。
修复：在 `get_paper_questions` 与 `grade_answers` 的两处契约里写明
**"格式判断是工具的事，你只管原样转发"**，并列出可接受的写法。
实测同一条 "AAAAA" 现在正常批改：`grade_answers: 批改 5 题，正确 1/5`，且逐题讲了原因。

**（b）解析层确实有一批自然写法认不出来**（`debug/probe_answer_formats.py` 实测）：

| 写法 | 修复前 | 修复后 |
|------|--------|--------|
| `AAAAA` | 可以 | 可以 |
| `AAAAAAAAAAAA`（多打几个 A） | **识别不了** | 整组都判 A |
| `全都选A` / `我选AAAAA` | **识别不了** | 整组都判 A |
| `1.D2.B3.D4.A5.C`（题号连写没空格） | **整串被当成第 1 题的答案** | 逐题正确 |
| `第一题A第二题B第三题C`（中文题号） | **识别不了** | 逐题正确 |
| 第 2 组显示 6~10 号，学生写 `1.A 2.B` | **组内序号失效** | 组内序号与真实题号都认 |

对应改动：
- 题号标记支持**中文数字**（第一题/第三题）与**选项字母紧跟题号**（`D2.`）两种写法
  （原来数字前有个 `(?<![0-9A-Za-z])` 反查，导致 `D2.` 匹配不上，整串被并进第 1 题）；
- 新增"**整组同一个选项**"识别（`_ALL_SAME`：全都/全/都/一律… + 字母），
  以及"重复字母数 ≥ 题目数就认为整组同选项"；
  同时用长度门槛避免把"只答了前 3 题的 AAA"误扩成整组；
- 恢复"**组内第几题**"兜底：查不到题型内序号时按在当前组内的位置定位。
  （这条是我上一轮引入的回归：非选择题的第 2 组会因为查不到 6~10 而整组解析失败。）
- `explain_question` 的 `no` 参数同理：题号在不同题型间会重复（选择题第 1 题 / 综合题第 1 题），
  所以**优先在当前这一组内解析**，全卷范围内只有唯一对应时才采信，
  否则返回 `ambiguous` 让模型补 qids —— 绝不静默挑一个题型
  （和 1.1 的 `display_num` 是同一类坑）。

### 1.16【中等】前端：每个 token 重渲染 Markdown 导致图片疯狂闪烁

`course_agent/static/chat.html` 的 `appendToBubble` 每个 token 都
`bubble.innerHTML = renderMarkdown(rawText)`。出题时一屏 5 张图，
**每次重渲染都会销毁并重新创建 `<img>`，浏览器于是反复重新请求图片**，
还会因为 Markdown 未闭合（`![题目](` 只写了一半）出现跳变。

**修复**：流式期间只渲染纯文本（`textContent`），`done`/`finalizeAIMessage` 时
一次性渲染 Markdown。同时补上 `error` 事件在气泡里的可见提示（原来只写进"思维过程"面板，
用户看到的是一个永远空白的回答）。

### 1.17【严重】选项字母只认 A–D：答 E 认不出，而且会静默丢字母

**用户实测反馈**：写完五道题，其中一题答了 E，"它没识别出来"。

`_LETTERS = re.compile(r"[A-Da-d]")` —— 全项目的选项字母范围都写死在 A–D。
后果分三档，**最危险的不是"认不出"，而是静默错位**：

| 学生写的 | 修复前 | 修复后 |
|----------|--------|--------|
| `1.E` | 认不出（提示"没从这段里认出选项字母"） | 判 E |
| `1.A 2.B 3.C 4.D 5.E` | 第 5 题丢掉 | 全对 |
| `ABCDE` | **E 被静默丢弃，且没有任何提示** | 按位对应 A–E |
| `AEBCD` | **丢 E 后变成 ABC D，后面全部错位 → 批改结果全错** | 正确对齐 |
| `全都选E` | 认不出 | 整组判 E |
| 答案字段本身是 `E` 的题 | **永远判不了**（"选项答案缺失或不是字母"） | 正常批改 |

最后两行是连带的：`grading_basis` 里判断"答案是不是字母"也用的 A–D，
所以答案键是 E 的题会直接落到 `correct=None`。

**修复**：范围放宽到 **A–H**（真实试卷最多见过 A–E，留余量），
并把所有相关正则（选项提示词、多选、整组同选项、非选择题的字母排除、
题号连写 `D2.` 的反查）一起改掉。

**放宽带来一个新风险**，必须同时挡住：A–Z 会让 `"the answer is B"`
里的 a/n/s/w/e/r 被当成选项字母串，于是加了形状校验
`_POSITIONAL_OK`（整段只能由选项字母/数字/分隔符组成），
并加了"解析不了就如实返回空"的规则 —— 见下一条。

**顺带修掉一个更早的坏兜底**：`"ABCDEFGHIJ"`（10 个字母 / 5 道题）
原来会退化成"整段塞给第 1 题"，等于凭空造出一个答案。
现在只含字母数字的短标记解析不了时一律返回空 + 说明。

> 关于"为什么会有 E 选项"：题库里**没有任何 E 选项**
> （实测选项标记 A×121 / B×122 / C×123 / D×121），抽样的试卷扫描件也是 A–D。
> 经用户确认，那次答 E 是**乱答**（题目只有四个选项），
> 期望行为就是"正常判错" —— 已加测试固化，详见第八节。

### 1.18【严重】"继续刷题"时推进了进度却没把题目发出来

**用户实测反馈**：做完一组后说"继续刷题"，它（游标）到了下一组，**但一条题都没给**。

根因是两层的：

**（a）出题工具只给了"排版示例"，没给成品文本。**
`get_paper_questions` 返回 `_render_example`（一段题目列表）并让模型
"照这个样子展示"。模型有时候只回一句"好的，这是下一组"就结束了 ——
**题目没贴，但游标已经前进了**，那一组就被静默跳过，学生再也见不到。
修复：像 `list_papers` 那样直接给出**可以发出去的成品文本** `reply_text`，
并在 `_guide` 里写明"题目必须整组出现在回复里"。

**（b）模型只在嘴上答应重发。**
补测"我没看到题目"时，模型回：
> 很抱歉，可能是由于格式问题导致题目没有正确显示。请稍等，我将重新发送这组题目。

—— 然后**没有调任何工具**，一条题也没发。
修复分两处：
- `get_paper_questions` 加**重发守卫**：学生说"没看到题/题目呢/再发一遍"且模型没指定组号时，
  重发**当前这一组**而不是顺着游标往前走（否则整组被跳过）；
- 主循环加**一次确定性纠偏**：学生说没收到题、当前确实有组、这一轮又没调过出题工具时，
  追加一条系统提示要求它立刻用同一组号重发（**只纠偏一次**，避免死循环）。

**验证**（`debug/verify_e_and_recovery.py`，真实 LLM）：

```
【学生】继续刷题              → 第 2 组 5 题全带图 ✅
【学生】我没看到题目          → 触发纠偏 → get_paper_questions(group_index=2)
                                → 重发同一组 5 题 ✅（不再是只道歉）
```

## 二、知识库检索的缺陷

### 2.1【严重】课本处理器必然抛 TypeError，整条课本分支不可用

**位置**：`knowledge_pipeline/textbook_processor.py:112`

```python
level1 = [(t[1], t[2]) for t in toc if t[1] >= 1 and t[0] == 1]
#                                       ^^^^ PyMuPDF 的 TOC 是 [level, title, page]
#                                            t[1] 是标题字符串 → "标题" >= 1 直接 TypeError
```

三本课本 TOC 全部非空（26 / 59 / 290 条），所以**课本处理 100% 失败**；
而 `pipeline.process_directory` 只用 `print("[错误]")` 吞掉异常，建库照样报"成功"，
课本知识静默缺失。

**修复**：改为 `t[2] >= 1` 并加 `len(t) >= 3` 防护；`process_directory` 改为
`logger.exception` + 统计失败文件并在结尾汇总。

### 2.2【严重】`_chunk_fixed` 在 `overlap >= chunk_size` 时死循环

```python
start = end - overlap      # size=100, overlap=100 → start 原地踏步
while start < len(text):   # 永不结束，chunks 无限增长直到 OOM
```

触发路径就是命令行参数：`python build_knowledge.py --chunk-size 100 --overlap 100`
（`build_knowledge.py` 对此没有任何校验）。

**修复**：`overlap = min(max(0, config.overlap), size - 1)` 并记警告；
推进改为 `start = max(end - overlap, start + 1)`。

**验证**：`chunk_size=100, overlap=100/150/99/0` 现在都能毫秒级返回（原来 15 秒超时被杀）。

### 2.3【严重】BM25 索引缓存永不失效

`_get_bm25()` 只在 `self._bm25 is None` 时重建，而
`add_document` / `build_from_dir` / `remove_document` / `clear`
**全都没有重置它**。于是服务运行期间新导入的文档对关键词检索永远不可见，
混合检索名存实亡；`clear()` 之后整份索引都是过期的。

**修复**：新增 `_invalidate_bm25()`，在每个写操作后调用。

### 2.4【中等】`_classify_doc` 硬编码基目录，绝对路径直接崩

```python
rel_parts = file_path.relative_to(base_dir).parts    # base_dir = Path("data")
```

文档里推荐的 `python build_knowledge.py --add-file "<Windows 绝对路径>"` 会抛
`ValueError: '...' is not in the subpath of 'data'`。

**修复**：两边都 `resolve()` 后再算相对路径，失败则退回按全路径判断。
（修的过程中还踩了一次"判断用 resolve、计算用原值"的错配，已在代码注释中记下。）

### 2.5【中等】懒加载单例无锁 + BM25 三字段分步赋值

FastAPI 的同步端点跑在线程池里，`_collection` / `_bm25` / `_kb_instance` 都是
check-then-act：并发首次检索会重复建 `PersistentClient`、重复全量建 BM25；
更糟的是 `_bm25` 已就绪而 `_bm25_ids` 正被替换时会 `IndexError`。

**修复**：加锁并改"先建局部变量、最后一次赋值"。
注意锁必须是 **`RLock`** —— `_get_bm25` 持锁后还会调 `_get_collection`，
普通 `Lock` 会自锁死（我在修复过程中真的踩到了，进程卡死 6 分钟才定位到）。

### 2.6【严重·原先被低估】`score = 1 - distance`：域外查询会算出负分，且阈值形同虚设

审计初稿认为"L2 距离被当成余弦相似度，score 恒为深负数"。我第一次核实时只采了几个
**课内**样本，看到 `d < 1`、分数为正，于是把它降级成"隐患"。**扩大样本后发现判断错了**：

```
向量模长: min=1.000000 max=1.000000   → 全部是单位向量（cos = 1 - d²/2 严格成立）

                      L2 距离    score=1-d    cos=1-d²/2
域内 死锁的四个必要条件      0.6014     0.3986       0.8192
域内 进程调度算法         0.6728     0.3272       0.7736
域内 分段和分页的区别       0.8188     0.1812       0.6648   ← 旧算法判成"相关度不高"
域外 今天北京天气怎么样      1.2496    -0.2496       0.2192   ← 负分！
域外 怎么炒西红柿鸡蛋       1.4040    -0.4040       0.0143   ← 负分！
域外 推荐几部好看的电影      1.2619    -0.2619       0.2038   ← 负分！
```

两个都是真问题，不是隐患：

1. **域外查询 L2 距离必然 > 1**（实测 12 条全部如此），`score = 1 - d` 直接变负 →
   触发 `max(max_vec, 0.001)` 把归一化分母钳到 0.001，向量分被放大到 ±10⁴，
   0.6/0.4 权重失效、排序反转。**每个课外问题都会走到这条路径**。
2. 阈值判定被写反了方向：`search_knowledge` 用**归一化融合分**和绝对阈值 0.3 比较，
   而融合分按本次最大值归一化、排名第一恒 ≥ 0.6，**这两个 `< 0.3` 分支从来没生效过**
   （补搜课本 + 提示联网都成了死逻辑）。而真正衡量"够不够"的绝对量，
   旧算法下 12 条课内样本只有 7 条过得了 0.3 —— 方向正好反了。

**修复**（`rag_tool.py`）：
- 新增 `distance_to_similarity(distance, space)`，按 collection 的**实际空间**换算：
  L2 用 `cos = 1 - d²/2`（单位向量下严格成立），cosine/ip 用 `1 - d`，结果截断到 `[-1, 1]`；
- `_hybrid_search` 里把**绝对相似度 `sim`** 和**归一化融合分 `score`** 分开：
  `score` 只用于排序，`sim` 才用于"够不够"的判断；
- 两个阈值判定改用 `sim`，阈值收敛为 `config.RELEVANCE_THRESHOLD`（默认 0.55）；
- 新建 collection 时显式指定 `hnsw:space=cosine`（对历史 l2 库无害：实测
  `get_or_create_collection` 传新 metadata 并**不会**改写已存在 collection 的空间，
  所以老库继续走 L2 分支，代码两种空间都兼容）。

**阈值取值依据**（`debug/check_threshold.py`，域内/域外各 12 条）：

```
                       域内最低    域外最高    能否分开
score = 1 - d           0.1812     0.0240      域内 12 条里只有 7 条 ≥ 0.3
cos   = 1 - d²/2        0.6648     0.5237      0.55 可把 24 条 100% 分开
```

**验证**（`debug/verify_score_fix.py` / `debug/regress_retrieval.py`）：

```
课内 6 条被误提示联网: 0        （修复前域内大量误判）
域外 6 条漏提示联网:   0
课内检索排序不变：死锁 0.81 / 虚拟内存 0.76 / TCP 0.83 / GBN 0.71
route_after_executor：结果充足→synthesizer，不足→web_search_fallback，历史陈旧标记→synthesizer
```

> 教训：只用 6 个样本 + 全部来自课内，就会把"每个课外问题都会踩的 bug"误判成隐患。
> 判断"阈值/分布"类问题必须**同时采域内和域外样本**。

## 三、Agent 架构与节点缺陷

### 3.1【严重】planner 对"合法但结构不符"的 JSON 抛未捕获异常

只 `except json.JSONDecodeError`。以下都会让 `AttributeError` 冒出去、整次请求 500：

| 模型返回 | 旧行为 | 新行为 |
|----------|--------|--------|
| `[{"tool": "search_knowledge"}]` | AttributeError | 回退默认计划 |
| `{"steps": {"tool": "x"}}` | AttributeError | 回退默认计划 |
| `{"steps": ["search_knowledge"]}` | 返回空计划（=不检索直接作答） | 回退默认计划 |
| `{"steps": [{"tool": "search_knowledge", "query": "死锁"}]}` | 正常 | 正常 |

**修复**：校验层级结构、跳过非 dict 元素、"steps 非空但一条都用不了"也回退默认计划。
（顺带发现 `nodes.py` 里用了 `logger` 但**没导入**，已补。）

### 3.2【中等】`route_after_executor` / `synthesizer` 把历史当本轮

`state["messages"]` 里有 checkpointer 累积的历史，而两处都遍历**全部**消息：

- 上一轮的"知识库中未找到相关内容"标记会让本轮凭空多跑一次联网搜索；
- 本轮只调 `get_course_info`（返回 31 字符）→ 命中 `len(combined) < 100` → 白跑一次联网；
- 用户这轮说"谢谢"，synthesizer 仍拿**上一轮**的检索结果拼进 prompt（实测）。

**修复**：新增 `_current_turn_tool_messages()`，以最后一条 `HumanMessage` 为界切分；
`get_course_info` 这种元信息不参与"够不够"的长度判据。

### 3.3【中等】`bind_tools` 就地改写全局单例

```python
def bind_tools(self, tools):
    self._tools = [...]      # 改的是全局 llm 单例
    return self              # 同一个对象
```

`nodes.py` 里 `llm_with_tools = llm.bind_tools(tools)` 之后，
**planner / synthesizer 这些本该发纯文本请求的节点也带上了 8 个工具定义**，
模型可能返回 `tool_calls` 而 `content=""`，planner 静默退化到兜底计划。

**修复**：`bind_tools` 返回 `copy.copy(self)` 的新实例。

### 3.4【中等】LLM 批改异常被静默吞掉，学生直接判错

旧 `tools.py:281` 是 `except Exception: pass` → `return False, "答案需要人工核对。"`。
401 / 429 / 超时 / JSON 解析失败全都等价于"判错"，无日志、无重试，主观题正确率系统性偏低。

**修复**：区分"批改失败"（`correct=None`，需人工核对）与"答错"；
补 `logger.error` 与 429 退避重试；`qbank.grade_answer` 用 `needs_manual` 显式标注。

## 四、工程化 / 配置 / 部署缺陷

### 4.1【严重】健康检查接口不存在，测试长期失败

`GET /` 被改成 302 跳 `/chat`，但 `tests/test_auth.py::test_health_no_auth`
仍在断言 `/` 返回 JSON → **README 写"88 项通过"，实际一直是 1 项失败**。
`docker-compose.yml` 的 healthcheck 也在探 `/`。

**修复**：新增 `GET /health`（返回状态 + 知识库分块数 + 题库题数），
`/` 保留跳转；更新测试与 compose healthcheck。

### 4.2【中等】JWT"未配置则跳过认证"是死代码

```python
JWT_SECRET = _optional("JWT_SECRET", "") or _secrets.token_hex(32)
#                                           ^^^ 空值也被填成随机串
```

于是 `auth.py` 里 `if not JWT_SECRET: 跳过认证` **恒为 False**。
而 `.env.example` 明确写着"JWT_SECRET 为空则不开启认证"、
"API_KEY 为空则不开启认证"，文档与实际行为相反。

**修复**：`config.py` 增加 `JWT_SECRET_IS_CONFIGURED` 标志区分"未配置"与"已配置"，
`auth.py` 用 `JWT_ENABLED` 判断。

### 4.3【中等】web_search 的 429 重试完全失效

`tools.py` 抛的是 `APIError`，而 `errors.py:65` 只捕获
`RateLimitError` / `requests.HTTPError` —— 父类异常不被捕获，装饰器直接放行，等于没有重试。

### 6.2 `memory.py` 摘要压缩：从死代码接进真实链路

## 八、已确认结案：那道"答 E"的题

**结论：不是数据问题，就是乱答；四选项题答 E 应当正常判错。**
（已由用户确认："那道答 E 的题就是我在乱答，只有四个选项，需要正常判错"）

排查过程与结论：

- 题库里**没有任何 E 选项**（实测选项标记 A×121 / B×122 / C×123 / D×121）；
- 抽查 `2019秋本部计算机网络模拟题_Q1_p2.png`，扫描件确实是 4 个选项（A–D）；
- 所以不存在"抽取时漏了第 5 个选项、答案键整体错位"的数据问题，**无需修数据**。

**但这条反馈暴露的解析缺陷是真问题**，也正是放宽字母范围要达到的效果 ——
关键是 `correct` 必须取 `False`（判错）而不是 `None`（判不了）：

```
四选项题（正确答案 D / B / D / A / C）答 E：
  第1题 -> 判错  解析='正确答案是 D。'      ← 期望行为
  第2题 -> 判错  解析='正确答案是 B。'
  ...
整组乱答：'1.E 2.E 3.E 4.E 5.E' / 'EEEEE' / '全都选E'
  -> 批改 5 题，判错 5，判不了 0          ← 一题都不能"没认出"而跳过
```

**为什么以前做不到"判错"**：范围写死 A–D 时，E 根本提取不出来 ——
`'1.E'` 提取到空字符串（判不了），`'ABCDE'` 把 E 静默丢掉（第 5 题不批）。
放宽到 A–H 之后才可能"把 E 当成一个有效作答、然后判它错"。

已加测试固化这条要求（`test_out_of_range_option_is_judged_wrong_not_unjudgeable`
与 `test_out_of_range_option_in_bulk_is_graded_not_skipped`），
防止以后有人"顺手"把范围收回去。
